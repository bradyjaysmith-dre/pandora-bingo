## Summary

Three major platform features plus deployment fixes. The game is now self-contained enough for solo play, serves fresh genre pools dynamically, and tracks player history across sessions.

---

## Features

### 1. Solo Mode

The host can start a game alone — no other players required.

- New **⚡ Play Solo** button in the lobby (host-only)
- Emits `host:solo_start` to the server
- Server sets `room.soloMode = true` and moves to picking phase
- After the host confirms picks, server immediately calls `startCountdown` and emits `game:playing` — waiting screen is bypassed entirely
- Works with all game modes and pick modes

**Files changed:** `server/index.js`, `client/src/components/LobbyScreen.jsx`

---

### 2. Dynamic Song & Artist Pools

Genre pools are now refreshed from Last.fm on every room creation.

- New `server/dynamic-songs.js` — async fetch from Last.fm `tag.gettoptracks` and `tag.gettopartists`
- Results cached to `server/song-cache.json` (auto-generated, gitignored)
- Cache is loaded on startup; updated after each successful fetch
- Fallback chain: **Last.fm API → disk cache → hardcoded static pool**
- Pool update is async and non-blocking: static pool is sent immediately, then `room:pool_updated` event patches the client silently
- Client listens for `room:pool_updated` and updates room state in App.jsx

**Genre → Last.fm tag mapping:**
| Genre | Tag |
|-------|-----|
| Pop | pop |
| Hip-Hop | hip-hop |
| Rock | rock |
| R&B | rnb |
| Country | country |
| Electronic | electronic |

**Files changed:** `server/dynamic-songs.js` (new), `server/index.js`, `client/src/App.jsx`

---

### 3. Leaderboard

Persistent cross-session player stats tracked by name.

- New `server/leaderboard.js` — JSON-file persistence (`server/leaderboard.json`)
- Stats tracked per player: `gamesPlayed`, `songMatches`, `artistMatches`, `wins`
- `getOrCreate(name)` registers a player on first join; returns existing record on subsequent games
- `recordGameResult(name, { matches, won, pickMode })` called at game end for every confirmed player
- `pickMode` determines whether matches increment `songMatches` or `artistMatches`
- **Name uniqueness per room** — joining with a duplicate name in the same room returns an error: *"That name is already taken in this room."*
- REST endpoint: `GET /api/leaderboard` — returns all players sorted by total matches desc, then wins desc
- New `client/src/components/LeaderboardScreen.jsx` — full leaderboard UI with rank, name, total matches, song matches, artist matches, wins, games played; styled with game-show aesthetic
- **🏆 Leaderboard** button added to HomeScreen

**Files changed:** `server/leaderboard.js` (new), `server/index.js`, `client/src/App.jsx`, `client/src/components/HomeScreen.jsx`, `client/src/components/LeaderboardScreen.jsx` (new)

## Deployment Notes

On Replit, after any code update:
```bash
git pull
cd ~/workspace/client && npm run build
bash ~/workspace/start.sh stop
# kill any stale process on port 3002 if needed: kill $(lsof -t -i:3002)
bash ~/workspace/start.sh
```

The `leaderboard.json` and `song-cache.json` files are auto-generated on first run and gitignored. They persist on the Replit filesystem across restarts.

## Known Limitations

- Leaderboard identity is name-only — no passwords. A player who changes their display name starts a new record.
- Last.fm API uses a shared public API key. If rate-limited, falls back to cache gracefully.
- Solo mode works with Standard game mode out of the box; Newlywed and Gong Show solo flows are functional but designed for multi-player social dynamics.
