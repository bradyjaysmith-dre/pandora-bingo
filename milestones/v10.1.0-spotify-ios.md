## Context

After v10.0.0 launched, live testing revealed that Spotify auto-detection failed for an iPhone host playing music through the iOS Spotify app. Android hosts on the same network worked fine. The issue was traced to a combination of iOS-specific Spotify API behavior and token expiry handling.

---

## Fixes

### 1. Relaxed `isPlaying` Gate

**Problem:** The polling loop had `if (!track || !track.isPlaying) return` — if Spotify reported the track with `isPlaying: false` (common on iOS during brief state transitions, background mode, or local playback contexts), the song was silently skipped entirely.

**Fix:** The server now processes the track regardless of `isPlaying` state. The `isPlaying` flag is still used to decide whether to send the `spotify:now_playing` UI update to clients, but a song is matched and scored even if the flag is false at the moment of polling.

```js
// Before
if (!track || !track.isPlaying) return;

// After
if (!track) return;
if (track.isPlaying) {
  io.to(roomCode).emit('spotify:now_playing', { track });
}
// song matching proceeds regardless
```

**File:** `server/index.js`

---

### 2. Automatic Token Refresh

**Problem:** Spotify access tokens expire after 1 hour. If a game session ran long, polling silently failed with auth errors — no songs detected, no visible error to the host.

**Fix:** Before each poll, the server checks if the token is within 60 seconds of expiry. If so, it calls `spotify.refreshToken()` and updates the stored token for the room. Failure to refresh is logged but non-fatal (polling continues with the old token).

`expiresAt` is now stored when the token is first saved (`connectedAt + 3600s`).

**File:** `server/index.js`

---

### 3. Manual Song Fallback in Spotify Host Tab

**Problem:** Even with the above fixes, the Spotify Web API fundamentally cannot always see playback on iOS (local device context). There needed to be a reliable human fallback.

**Fix:** A collapsible `<details>` section added to the Spotify host tab in GameScreen — **"⚠️ Song not detected? Tap to mark manually"** — expands to show the full song pool as tappable cards, identical to manual mode. Host taps a song → `host:play_song` is emitted → scores update for all players normally.

This works with all pick modes (songs and artists) and all game modes.

**File:** `client/src/components/GameScreen.jsx`

---

### 4. Gitignore Runtime Data Files

**Problem:** `server/leaderboard.json` and `server/song-cache.json` were auto-generated on first run and committed, causing `git pull` to fail on Replit with "untracked files would be overwritten."

**Fix:** Both files added to `.gitignore` and removed from git tracking (`git rm --cached`). They are now treated as runtime-only data on each deployment and never committed.

**File:** `.gitignore`

## Known Remaining Limitation

iOS Spotify detection is best-effort. If the iPhone Spotify app is backgrounded or the iOS system suspends the audio session, the API may return `null` entirely. The manual fallback is the reliable path for iPhone hosts.
