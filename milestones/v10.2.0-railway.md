# Milestone: v10.2.0 — Railway Deployment

**Date:** 2026-05-11
**Branch:** main
**Tag:** v10.2.0

---

## Context

Pandora Bingo was previously hosted on Replit's free tier, which sleeps after ~5 minutes of inactivity. This required keeping a browser tab open during game nights and caused cold-start delays for players. Railway was chosen as a replacement for always-on, zero-timeout hosting with automatic deploys on push.

---

## Changes

### 1. `railway.json` added

A `railway.json` config file was added to the repo root to define the build and start commands for Railway's Nixpacks builder:

```json
{
  "build": {
    "buildCommand": "cd client && npm install && npm run build && cd ../server && npm install"
  },
  "deploy": {
    "startCommand": "node server/index.js",
    "restartPolicyType": "ON_FAILURE",
    "restartPolicyMaxRetries": 3
  }
}
```

Railway builds the React frontend (`client/dist`) as part of deployment. Express serves the built frontend as static files — single port, no separate frontend server.

### 2. Environment variables set on Railway

The following variables are configured in Railway's Variables tab:

| Variable | Value |
|---|---|
| `SPOTIFY_CLIENT_ID` | (from Spotify Developer Dashboard) |
| `SPOTIFY_CLIENT_SECRET` | (from Spotify Developer Dashboard) |
| `SPOTIFY_REDIRECT_URI` | `https://pandora-bingo.up.railway.app/auth/spotify/callback` |
| `NODE_ENV` | `production` |

`PORT` is injected automatically by Railway — not set manually.

`NODE_ENV=production` activates production mode in `server/index.js` (same-origin CORS, static file serving, production log output).

### 3. Spotify Developer Dashboard updated

The Railway callback URI was added to the Spotify app's redirect URI allowlist:
```
https://pandora-bingo.up.railway.app/auth/spotify/callback
```

### 4. No code changes required

The existing `getPublicBaseUrl()` helper in `server/index.js` already handles Railway correctly — it reads `x-forwarded-host` (set by Railway's proxy) and derives the full callback URL dynamically. The `isProduction` flag triggers on `NODE_ENV=production`. No hardcoded URLs were needed.

## Deployment Workflow Going Forward

Railway auto-deploys on every push to `main`. No manual shell steps needed:

```bash
git add .
git commit -m "your message"
git push
# Railway picks up the push and redeploys automatically
```

### Known Limitation — Spotify Whitelist

The Spotify app is in **Development mode**. Only accounts explicitly whitelisted in the Spotify Developer Dashboard can authenticate as host. Players (non-hosts) are not affected — they never authenticate with Spotify. To open hosting to any Spotify account, submit for Spotify's Extended Quota review.
